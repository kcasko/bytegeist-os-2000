# Recovery and release preparation plan

Continue the approved product brief through a locally complete P0 experience. No public hosting, DNS, remote publication or submission without confirmation.

1. BG-201: Independent pure incident reducer and typed context. Test consent, explicit execution, process termination, startup persistence, quarantine, scan, reboot reinfection and verified recovery. Keep window and portfolio state independent.
2. BG-202: ByteWire opt-in execution confirmation and prevention-to-infection route. Task Manager, Startup Manager, ByteDefender, Event Viewer and final incident report. Bounded nonflashing desktop symptom, permanent simulation exit/reset controls outside game windows. Evidence and contextual hints explain process versus persistence. All actions local and deterministic.
3. BG-101: Typed portfolio case studies, education/credentials and contact with source verification. Preserve existing sites.
4. BG-301: Browser tests for full recovery, mistakes/reinfection, exit during infection, portfolio access, touch emulation, narrow viewports and reduced motion. Accessibility audit; fix meaningful issues with regression tests. Local production preview validation.
5. BG-302/303: Read official challenge rules and current Amplify documentation, prepare release checklist, screenshots and submission draft. Explicitly leave public deployment, live AWS evidence and submission pending confirmation.

Core recovery invariant: process stopped AND startup disabled AND file quarantined AND clean scan followed by simulated reboot. Stopping symptoms alone never awards recovery. Reboot with live persistence and available file relaunches process. Ending/resetting simulation clears incident state, never desktop/portfolio state. No real executables, downloads, external targets or credentials.
