# More convincing fictional infection

Approved direction: expand the one-box symptom into a desktop incident while preserving the existing portfolio and recovery rules.

- Test symptoms first: active process produces multiple fictional warnings over time; dismissing symptoms does not terminate process; containment/exit removes all effects; reboot reinfection returns effects.
- Add a focused InfectionEffects component with at most three nonmodal in-page warning windows, returning on a bounded timer. Never autofocus, open browser windows, play sound, flash, imitate actual browser chrome, or request payment/credentials.
- Hijack only the fictional wallpaper, add a rogue shortcut, and show explicitly simulated CPU/tray activity. An activity view explains the fake symptoms and links to recovery tools.
- Desktop warnings remain clear of recovery controls; maximized real apps suppress floating symptoms. Below 1280px, reserve a 44px activity strip instead of floating warnings over app content. Global exit/reset stay separate and always available.
- Keep incident reducer invariant unchanged: process termination stops symptoms, startup persistence can restore symptoms on reboot. Reset/exit clears the timer and transient warning state.
- Run component, production browser, accessibility and mobile tests; capture before/after and package a new candidate. No public publishing.
